# C code style

Rules for `runtime/*.c` and `runtime/*.h`. The sibling of [CODE_STYLE.md](CODE_STYLE.md),
which governs `.psm`.

The C here is not general-purpose C. It is one side of a seam: the other side is
generated code that the ownership analysis has already reasoned about. Most of
what follows is a consequence of that, not a matter of taste.

---

## The invariants

These fail a generation later, or at run time in someone else's program, with
nothing pointing at the cause.

### Allocations returned to Prismio go through `rt_base_alloc`

Strings are affine, so codegen emits a release for every owned `String` it is
handed. The allocation at the other end of that pairing must come from the
allocator the verify ledger tracks. **Both ends have to swap together.**

The seam is in [`prismio_runtime.h`](runtime/prismio_runtime.h):

```c
#ifdef PRISMIO_AIF_VERIFY
#define rt_base_alloc(n) aif_verify_alloc(n)
#else
#define rt_base_alloc(n) malloc(n)
#endif
```

A bare `malloc` whose pointer is returned to Prismio does not leak. It reports as
`release of a pointer that is not live` — a **violation**, which reads as
unsoundness where there is none, and it hides real violations in the noise. This
invariant was stated at the top of `lang_runtime.c` and applied only there;
`program_support.c` returned seven kinds of owned string from bare `malloc` and
made every filesystem allocation invisible to `--verify`.

The converse is equally load-bearing: **an internal temporary that this runtime
frees itself must stay on plain `malloc`/`free`.** Routing one through the ledger
records an allocation that no generated release ever pairs with, which reads as a
leak. `list_modules` allocates both kinds, four lines apart.

If a C library allocates for you and you return that pointer — `getcwd(NULL, 0)`,
`strdup` — copy it into `rt_base_alloc` memory and free the original.

### A returned `String` must be freeable on every path

Never return a string literal from a function declared to return `String`. Static
storage contributes no allocation site, and one such return makes the whole
function's result unowned, so the paths that *did* allocate leak too. Allocate a
one-byte copy instead. `str_substring` and `str_trim` have carried this rule
since values became affine; the comment in `str_trim` about the all-whitespace
case is exactly it.

### The contract is part of the signature

Every function returning a pointer that Prismio will hold falls into one of two
groups, and the answer belongs in a `std/*.psm` wrapper:

- **allocates** → the wrapper declares `produce(free)`
- **returns a pointer it does not own** → the wrapper declares `alias`

Getting this backwards on `cli_arg` — which returns a pointer into `argv` — hands
`argv` to the deallocator. That is a different and much worse category than a
leak. If a new function's answer is not obvious from three lines of its body, it
is written wrong.

### A constant shared across the seam has one spelling everywhere

The element-ownership mode is one wire protocol with three definitions —
`AIF_ELEM_*` in `src/ir/context.psm` (what codegen emits), in `aif_support.c`
(what the analysis answers), and in `lang_runtime.c` (what the runtime compares
against). The int crosses two seams and is never re-derived, so a variant added
to one list and not the others still builds and then releases elements with the
wrong deallocator.

Two rules follow. **Same prefix in all three**, because the odd one out is what
makes drift invisible — these were `XEFY_ELEM_*` in `lang_runtime.c` until
2026-08-23, so a grep for `AIF_ELEM_CYCLE` found two of the three sites and gave
no sign the third existed. And **a test that compares the tables**, because a
comment saying they must agree is not a check;
`run_elem_mode_agreement_test` in `tests/test_runner.py` is.

If you add a shared constant, add it to that test.

### `extern fn` names are the ABI

Renaming a C function is a breaking change to the language's runtime surface, not
a refactor. `tests/*.psm` and every application declare these by name.

## Files and modules

**A file is named after what it holds, and holds only that.** The current
offender is `aif_support.c` at 7014 lines, which is the inference engine, the
constraint solver, the tier assignment, the layout chooser, the manifest writer
and the verify ledger in one translation unit. That is six responsibilities and
six names.

Splitting a runtime source is not a free operation — the file list is duplicated
in four places and they are checked against each other:

1. `prismio_toolchain_files[]` in `runtime/build_driver.c`
2. `RUNTIME_SOURCES` in `tools/bootstrap.sh` and `tools/bootstrap.ps1`
3. `runtime/embedded_sources.h`, regenerated by
   `runtime/generate_embedded_sources.py`
4. `tools/check_source_lists.py`, which asserts 1 and 3 agree

Run the generator and `check_source_lists.py` after any change to the set, and
bootstrap two generations before believing it.

**`runtime/` splits in two and the dependency runs one way.** `lang_runtime.c`
and `program_support.c` are linked into every compiled program. `build_driver.c`,
`ir_symbols.c`, `aif_support.c`, `diagnostics.c` and `llvm-api-backend.c` are the
compiler's own. Backend may call runtime; runtime may never call backend. A
program that prints a string must not drag in LLVM.

**`static` unless it is called from another translation unit.** A non-`static`
function is part of the linked surface and shows up in the symbol table of every
program.

## Comments

The rule is [CODE_STYLE.md](CODE_STYLE.md)'s, unchanged, and it cuts both ways
sharply enough to be worth restating with numbers. Across `runtime/*.c` there are
107 banner-delimited comment blocks: **53 carry real prose and 54 are a title
between two rulers.**

**Delete the 54.** `// ===== String Comparison =====` above `str_compare` is
noise, and so is `// Copy prefix` above a `strncpy` into a buffer named `prefix`.
CODE_STYLE.md names the pattern directly: a section banner over three lines, and
comments that restate the code.

**Keep the 53, and write more of them.** These are the ones that carry what the
code cannot — why a decision was made, and what went wrong last time:

> `list_get` is deliberately NOT here any more, and the reason is a soundness bug
> this comment used to describe as fixed […] returning the argument's value set
> does not do that — it returns *the list*.

That comment is worth more than the function under it. A reader who deletes it to
"clean up" removes the only record of a bug that will be reintroduced.

The distinction is mechanical enough to apply without judgement:

| Delete | Keep |
|---|---|
| a title between rulers | a paragraph that names a constraint |
| what the next line does | why it is done that way and not the obvious way |
| a restatement of the signature | a measurement, with its number |
| `// TODO` with no owner or date | what was tried and refuted, and by what evidence |

When you delete a ruler, keep the prose that was inside it and let it sit
directly above the code as an ordinary comment.

## Writing the code

- **Early returns over nesting.** A guard clause is the shape, not a special case.
- **One responsibility per function.** Functions here are already short — the
  longest in `lang_runtime.c` is 40 lines — and that is worth keeping.
- **No wrappers for one caller.** Same rule as the `.psm` side.
- Declare loop variables at first use. This is C99 and the build has always been.
- Fixed-width types from `<stdint.h>` where width matters. `int` is fine for a
  count that indexes an array this runtime allocated.
- **Check every allocation that can fail on a path a user reaches.** The frontend
  may `exit(1)` with a message — it is a batch compiler and a failed allocation
  there is not recoverable. The linked runtime may not: it is inside someone
  else's program.

## Naming

| Kind | Convention | Example |
|---|---|---|
| Functions and variables | `lower_snake_case` | `str_concat`, `arena_depth` |
| Types | `PascalCase` | `StringArray`, `CycVisitor` |
| Macros and constants | `SCREAMING_SNAKE` | `PRISMIO_AIF_VERIFY` |
| File-local state | `static`, prefixed by area | `rt_arena_hint`, `g_prof_depth` |

Prefixes mark the seam: `str_`, `list_`, `arena_`, `rc_`, `cyc_`, `rt_`, `aif_`,
`ir_`, `diag_`, `chan_`. A new function joins an existing prefix or brings a new
area with a name.

## Before you commit

Same bar as the `.psm` side, because a runtime change reaches the next compiler
generation:

```bash
python3 runtime/generate_embedded_sources.py
python3 tools/check_source_lists.py
bash tools/bootstrap.sh --compiler <known-good> --out build/g1
bash tools/bootstrap.sh --compiler build/g1 --out build/g2
```

`g1` and `g2` must emit identical IR for `src/main.psm`. Then
`PRISMIO=$PWD/build/g2 python3 tests/test_runner.py`, then
`python3 tools/aif_differential.py --compiler build/g2`.

For anything touching allocation, also build a program with `--verify` and read
the ledger. **`violations` first, then `released` against `allocated`** — the
`allocated` and `leaked` counts are noisy run to run, and `violations` is the
number that means corruption.

## The standing refactor

Updated 2026-09-03, after a pass that did items 2 and 3 and part of 1. Everything
below was verified **byte-identical** against the pre-refactor compiler output
(4,448,611 bytes), two generations to a fixpoint, 277/277 fixtures, and the AIF
differential — which is the bar CLAUDE.md sets for a behaviour-preserving change.

### Done

- **The container layer is out of `aif_support.c`.** `runtime/aif_containers.c`
  and `.h` hold the allocation helpers, the growable bitset and the int vector —
  the layer that file's own header comment already named, and the one with the
  widest reach: `xmalloc` was referenced across 6,865 of its lines and
  `bits_test` across 5,766.

  **The layer was not contiguous, and that is the thing to know before splitting
  anything else out.** The fact encodings (`AIF_E_*`, `AIF_A_*`, `AIF_C_*`,
  `AIF_K_*`) sit *between* the allocation helpers and the bitsets. A first attempt
  cut by line range, swept the encodings into the new file, and left
  `aif_support.c` using constants it no longer defined. The sections interleave;
  a line range is not a boundary.

- **The 41 banner rule lines are gone** across `runtime/`, prose kept. The count
  in the previous version of this section (54) was stale.

- **The `rt_base_alloc` seam has one definition.** `lang_runtime.c` no longer
  defines its own copy ahead of its includes; `prismio_runtime.h` gained the
  `aif_verify_arm` declaration that copy was carrying, and is now included for
  the seam rather than only for the threading primitives.

### Left, with what the next attempt should know

1. **The rest of `aif_support.c`** (now 7,100 lines). The remaining five
   responsibilities are real, but the coupling is measured and it is dense: with
   six equal cuts, **42% of its static functions are referenced across a
   boundary**, and 26 have references spanning more than 1,500 lines —
   `nominal_find`, `candidates_clear`, `scope_lca` among them. Each crossing is a
   symbol that stops being `static` and joins the linked surface. Splitting
   further is worth doing, but it is a partition problem, not a cut: decide the
   six groups first, then measure crossings per grouping, and only then move
   text.

2. **`llvm-api-backend.c` — the premise here was partly wrong.** "IR construction
   and target/layout query, which do not call each other" holds only for target
   *selection*: `ir_target_select`, `ensure_target`, `ir_target_triple` and the
   `g_target_*` statics are self-contained in about 85 lines. The layout
   *queries* — `LLVMOffsetOfElement`, `LLVMABISizeOfType` — read the module's own
   data layout from inside IR construction and cannot be lifted out of it.
   Extracting 85 lines from 4,300 does not repay a new file and six list updates;
   a useful split of this file needs a different seam.

### Adding or removing a runtime source

The file list is duplicated in **six** places, not the four this section used to
claim, and `tools/check_source_lists.py` names each one it finds disagreeing:

1. `prismio_toolchain_files[]` in `runtime/build_driver.c`
2. the `prismio_embedded_text()` switch in the same file — **its case numbers are
   positional**, so inserting a file renumbers every case after it
3. `RUNTIME_SOURCES` in `tools/bootstrap.sh` and `tools/bootstrap.ps1`
4. `EMBEDDED_FILES` in `runtime/generate_embedded_sources.py`
5. the backend lists in `tools/package.sh` and `tools/package.ps1`
6. `runtime/embedded_sources.h`, regenerated by the script in 4

Run the generator and then `check_source_lists.py`, which is what tells you the
six agree, and bootstrap two generations before believing it.

**A failing compile inside the parallel loop reports as something else.**
`bootstrap.sh` compiles the misses in background jobs and its `EXIT` trap removes
the work directory, so the first error you see is a *different* file failing to
rename its object into a directory that no longer exists. Re-run with `--keep` to
see the real error.
